# Dependency Report - support baseline modernisation - 2026-08-07

## Scope

- Repository: `Herbertmt978/HA-ScorpionTrack-Integration` only.
- Home Assistant Core and its built-in integrations were not changed.
- The installed custom integration was checked read-only; no Home Assistant configuration or vehicle service was invoked.

## Summary

- Locked packages: 155, reduced from 223.
- Open GitHub Dependabot alerts before this update: 86 (29 high, 35 medium, 22 low).
- Expected open alerts after the new lockfile reaches the default branch: 1 high-severity upstream-constrained alert.
- Supported test baseline: Home Assistant 2026.8.0 on Python 3.14.2 or later in the Python 3.14 series.
- Licence issues: not checked in this focused vulnerability review; no direct runtime dependency was added.

## Remediation Applied

- Retired the Home Assistant 2025.1 / Python 3.12 compatibility lane and its vulnerable transitive dependency graph.
- Removed the legacy `pycares==4.5.0` compatibility override.
- Updated `pytest-homeassistant-custom-component` to 0.13.354, which resolves Home Assistant 2026.8.0 for the test environment.
- Raised the HACS minimum Home Assistant version to 2026.8.0 and the development requirement to Python `>=3.14.2,<3.15`.
- Regenerated `uv.lock` with its owning `uv lock` command, producing a single supported dependency graph.
- Updated the quality workflow, contributor documentation, issue template, changelog, Ruff target, and uv tool constraint to match that baseline.

Notable resolved versions include Home Assistant 2026.8.0, `aiohttp` 3.14.3, Pillow 12.3.0, PyJWT 2.13.0, `pycares` 5.0.1, pytest 9.0.3, and uv 0.11.31.

## Residual Finding

### High

GitHub Dependabot alert 84 remains applicable to `cryptography` 48.0.1:

- Advisory: `GHSA-g6cj-pr64-35w5`
- Vulnerable range: `>=44.0.0,<50.0.0`
- First patched version: 50.0.0
- Impact: distinguishable errors and timing in PKCS#7 EnvelopedData decryption can expose a Bleichenbacher oracle.

Home Assistant 2026.8.0 pins `cryptography==48.0.1` exactly. This repository does not import `cryptography` or use the affected PKCS#7 API, but the alert should remain open until a supported Home Assistant release carries `cryptography>=50.0.0`. Overriding Home Assistant's exact runtime dependency would make this repository's tests unrepresentative and is not recommended.

`uv audit` reports six records for `cryptography` 48.0.1. These represent three GHSA advisories duplicated by their PYSEC aliases. Two of the three GitHub vulnerable ranges end at 48.0.0, so GitHub correctly considers 48.0.1 unaffected by those two advisories. The advisory above is the one applicable Dependabot finding.
